## Decisions fixed before any power simulation (2026-10-27)
- Scenarios: `protocol/power/scenarios.json`.
  - pilot_informed = G4 pilot cell rates (LC 3/3, LD 3/3, MC 3/3, MD 1/3).
  - conservative = each pilot cell moved 0.05 toward the pooled mean (0.833), the common cell value
    under the null: LC/LD/MC 0.95, MD 0.383.
  - formula_predicted = 0.98 / 0.98 / 0.98 / 0.50 (Section 4 at the G3 operating points).
- Type-I calibration (Section 16: 0.035–0.065 over 2,000 null datasets) is checked at
  `null_calibration` (every cell 0.5). At high common rates most blocks have no contrast and a
  discrete exact test is conservative by construction (type-I well below α), which is not a
  calibration failure; the type-I error at the pilot's pooled level (0.833) is reported alongside.
- Search: B ∈ {6, 8, 10, 12, 14, 16, 20, 24}, σ_b ∈ {0, 0.5, 1.0}, 1,000 datasets × 1,000 sign
  draws (exact when B ≤ 9), seed 20261027 → `protocol/power/search.csv`.
- Rule: B = smallest value with power ≥ 0.80 (pilot_informed, σ_b = 0.5) and ≥ 0.70
  (conservative, σ_b = 0.5); B ≤ 24, else H1 is withdrawn.
- Confirmation at the chosen B: 2,000 datasets × 2,000 draws for pilot_informed and conservative
  (σ_b = 0.5), and 2,000 datasets for each null → `protocol/power/confirm.json`. If confirmation
  falls below the targets, the next larger B in the grid is confirmed in the same way.
- Master seed: from a NIST Randomness Beacon 2.0 pulse fetched after B is committed;
  seed = first 64 bits of the pulse `outputValue` (hex), recorded with the full pulse in
  `protocol/master_seed.json` before the schedule is generated.

## Clarification D1 — type-I calibration criterion (recorded before confirmation and freeze)
Found while verifying the G5 tooling: the search (same command and seed as step 1 of the runbook,
deterministic) gave a null_calibration type-I error of 0.009–0.037 across B and σ_b, below the
0.035–0.065 band of Section 16 even with every cell at 0.5.

Cause: every nonzero term of the Δ_A statistic has magnitude ½ (a_b, c_b ∈ {−1, 0, 1}), so the
locked sign-flip test is a two-sided sign test on the k nonzero terms. Its attainable sizes form a
lattice: with k = 24, P(|S| ≥ 10) = 0.064 and P(|S| ≥ 12) = 0.023, so the size at α = 0.05 is
0.023. No non-randomized exact test of this design can be held inside 0.035–0.065; the band
conflicts with the locked test (Section 12.1), whose validity (size ≤ α) is not in question.

Resolution, keeping the locked test unchanged: the Section 16 check is applied as
(i) validity — simulated type-I error ≤ α (+ 3 Monte Carlo SE), and (ii) calibration of the
implementation — simulated type-I error equal, within 3 Monte Carlo SE, to the exact size of the
sign test computed for the same simulated datasets (`frx.power.sign_test_size`). (ii) is a stricter
test of the code than the band. Power is computed with the same test, so B already reflects its
conservativeness. The B rule uses only the pilot_informed and conservative scenarios and is not
affected; that search selects B = 16 (pilot_informed 0.995, conservative 0.784 at σ_b = 0.5;
at B = 14 conservative is 0.674).

## First freeze withdrawn before registration (2026-10-27T08:19:52Z)
The first `frx freeze` ran although the test suite had just reported 1 failure (94 passed): a test
written before G5 asserted that the G5 values were still open, so it failed once they were fixed.
Section 18 G5 requires "tests pass", so that freeze did not meet the gate. No registration and no
RUN- ID existed. The freeze commit is kept in the history (tag `protocol-v3.0-freeze-withdrawn`),
FREEZE.json was removed in a separate commit, the stale test was replaced by a gate-state-independent
one, and `frx freeze` now runs the full suite itself and refuses unless it passes (the result is
recorded in FREEZE.json). B, the seed and the schedule are unchanged.
