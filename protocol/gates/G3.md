**Decision: 10 MiB × 1 for both sources** (author's choice 2026-10-26). Rationale:
M = 10 MiB: Tetragon Helm chart 1.7.1 default export file size, used for both sources. k reduced from the chart default 5 to 1 under Section 4.3 item 4: the largest k whose highest required rate (Q-c and calibration, H ~ 0.5: 341 API GET/s, 106 exec/s) lies inside the envelope measured in load_map.json (400 GET/s, 200 exec/s); k = 5, 3, 2 need 1257, 799, 570 GET/s. Decided from load-map metadata only, before any Q run.
A wider loss ramp also keeps r_M's 0.3–0.7 loss probability robust to run-to-run variation in
action duration (about ±0.04 per ±2 s at k = 1, against ±0.16 at k = 5).
Scope consequence (stated in the manuscript): the 2×2 is estimated at a 20 MiB store per source;
the calibration series covers H from 2 to 0.5.

### Defect found by Q and fixed before the pilot (QUAL-0033)
The pre-action source-health check compared the audit file size 2 s apart; a rotation inside
that window (size fell 10.25 MB) failed it (PA-SRC). At k = 1 this would abort about 4 % of
M-cell runs, always when the active file is new (offset o ≈ 0, maximum headroom), so the kept
runs would be biased toward loss. A new inode under the active name now counts as growth
(`audit_growing`, tested). The check never reads outcomes; in Q the abort was replaced by rule
and stays archived.

### Values fixed after Q (2026-10-27)
- NC action duration `timing.control_idle_s` = 4.1 s: median ACTION_REQUEST → TERMINATION_CONFIRMED
  over the 24 scored Q-a/Q-b runs (range 3.59–5.62 s).
- Platform fingerprint reference `host.fingerprint_stable_hash` = b64c25cd…a55f, collected as root
  exactly as sessions collect it (`qualification/g3/fingerprint_platform.json`). The stable hash now
  covers the platform only (host, tools, cluster images and configuration, audit policy); protocol
  files are hashed per session and in FREEZE.json, and the node boot ID is excluded so a reboot is
  not a platform change.
