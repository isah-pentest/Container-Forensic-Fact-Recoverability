### Correction to the first verdict
The original `capacity_report.json` (kept unchanged) failed only the completeness check
(3.19 audit, 11.1 Tetragon). Cause: `bytes_written()` keyed files by inode number, and the
kernel reuses inode numbers after old backups are evicted, so many rotated files were
merged. Fixed by tracking each inode *life* (a new life starts when its size drops), with
regression tests. The run was re-scored from its preserved files with
`frx capacity-reevaluate`; no rerun was needed.
